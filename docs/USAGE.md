# Gesture Lab — подробности

Короткий запуск — в [README](../README.md). Команды ниже выполняются из корня проекта.

`start.bat` и `start.sh` запускают `run.py`: он создаёт локальное окружение и устанавливает зависимости только при первом запуске или изменении `requirements.txt`. Передать параметры можно так: `bash start.sh --demo` или `start.bat --camera 1`. Подготовить окружение без открытия окна: `python run.py --setup-only`. На Intel Mac используются MediaPipe 0.10.21 и OpenCV 4.11 с Python 3.10–3.12; на остальных поддерживаемых платформах остаются основные версии из `requirements.txt`.

Настольная программа на Python: камера с отображением суставов обеих кистей и виртуальное стекло, которое растягивается между пальцами и искажает живое изображение. Средний палец показывает фотографию поверх камеры; GIF и обычные анимации временно выключены, их область скрыта — камера занимает всю доступную ширину. Интерфейс на русском, обработка в отдельном потоке, кадры камеры приложение не записывает.

Минималистичный тёмный интерфейс оставляет на главном экране камеру, её статус, измеренный FPS и кнопку запуска. Источник камеры, зеркало, скелет рук, профиль экспозиции, GIF и чувствительность собраны в сворачиваемой панели **«Настройки»**. Декоративный экран ожидания статичный, без дополнительного цикла анимации.

## Запуск

Из папки проекта:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

В Windows вместо `source` используй `.venv\Scripts\activate`.

На этом компьютере окружение `.venv` уже подготовлено. Быстрый запуск:

```bash
.venv/bin/python main.py
```

Сразу включить камеру при открытии окна: `.venv/bin/python main.py --start-camera`.

Нажми **«Включить камеру»**. При первом включении автоматически загружается официальная модель MediaPipe (~8 МБ); дальше используется локальный файл с проверкой SHA-256. Камера включается только по кнопке. Если камера не открылась, попробуй индекс `1` вместо `0` или закрой другое приложение, которое её использует.

Для камеры запрашивается 1280×720, MJPEG, 30 FPS. Фактическое разрешение каждого полученного кадра отображается над камерой рядом с FPS: если драйвер выбрал другой режим, интерфейс покажет его реальные размеры.

### Производительность

- **«Ускорение распознавания на GPU»** включено в настройках по умолчанию. Используется та же модель, две руки и те же пороги уверенности. Если GPU не инициализируется, приложение автоматически возвращается на CPU. Для ручного выбора CPU останови камеру и выключи флажок. Фактический backend виден в подсказке при наведении на FPS.
- Распознавание следующего кадра выполняется параллельно с отрисовкой предыдущего. Результат всегда остаётся привязан к своему исходному кадру; бесконечной очереди и подстановки старых суставов в новый кадр нет. Конвейер добавляет один кадр задержки. Распознавание искусственно не ограничивается до 10–15 FPS.
- OpenCV использует два рабочих потока вместо всех доступных. Геометрия искажений считается на разреженной сетке, затем координаты выборки интерполируются. Само изображение камеры, выборка текстуры и контуры остаются в исходном разрешении: камера не уменьшается до размера сетки. Цветовая обработка и смешивание перенесены в операции OpenCV, убраны лишние полноразмерные массивы.
- При сворачивании окна новые запросы распознавания и отрисовки приостанавливаются; после восстановления работа продолжается. Камера при этом остаётся открыта. Для её отключения нажми **«Остановить»**.

На этом ноутбуке в локальном замере обработчика без GUI, рук и активного эффекта частота осталась **30,1 FPS**, а нагрузка CPU снизилась с **92,5% до 50,5% одного ядра**. Это не проценты загрузки всего многоядерного процессора и не измерение энергопотребления GPU. Расчёт большого эффекта ускорился примерно с 120–140 до 25–35 мс. В контрольном тесте с эталонным фото двух кистей, подаваемым с частотой 30 кадров/с, эффект обычного размера давал 29,7–30 FPS, большой — примерно 27–30 FPS. Это не гарантия такой же частоты при любом движении рук, освещении и нагрузке других приложений. Системный профиль питания приложение не переключает.

### Настройка этой камеры

Для подключённой HD WebCam сохранён профиль `camera_profile.json`: ручная экспозиция 20 мс, отключено динамическое снижение FPS, автоматический баланс белого, подавление мерцания 50 Гц, умеренная резкость и коррекция яркости/гаммы. Захват использует два буфера: с одним буфером OpenCV на этой камере терял каждый второй кадр. При одинаковых настройках повторный замер показал **15,2 FPS** с одним буфером и **30,1 FPS** с двумя в 1280×720 MJPEG. Понижать разрешение не понадобилось. Полный обработчик с включённым распознаванием, но без рук и активного искажения в кадре, выдавал **30 FPS**; нагрузка от рук и эффектов может снижать частоту. В интерфейсе отображается измеренная частота обработки, а не только запрошенные у драйвера 30 FPS.

Флажок **«Профиль камеры: движение»** включает эти настройки при запуске камеры. Чтобы вернуть исходную автоэкспозицию, останови камеру, выключи флажок и включи камеру снова. Выбор сохраняется в `config.json`. Профиль применяется только к USB-идентификатору этой камеры, через `v4l2-ctl`; другие камеры и платформы не затрагиваются. Само приложение работает и без `v4l2-ctl`.

При слабом освещении короткая экспозиция требует дополнительного света перед лицом. Физическое направление камеры и отсутствие деталей у оптики нельзя исправить повышением разрешения или резкости.

Для просмотра интерфейса и анимаций без камеры, модели и загрузок:

```bash
.venv/bin/python main.py --demo
```

Можно указать камеру при запуске: `python main.py --camera 1`. Проверено на Python 3.14 под Linux; зависимости требуют Python 3.10 или новее. MediaPipe закреплён на проверенной версии `0.10.35`: версия `1.1.1` на этом компьютере завершалась при создании распознавателя.

### Интерактивное стекло двумя руками

1. Включи камеру и помести обе кисти целиком в кадр.
2. На каждой руке раскрой большой и указательный пальцы, как будто держишь боковые края небольшого экрана. Начни с указательных выше больших; после захвата кисти можно поворачивать. Остальные пальцы можно согнуть.
3. Одновременно соедини указательные пальцы друг с другом и большие пальцы друг с другом. Ненадолго удержи касание (~120 мс): оно включит фигуру. Просто показать раскрытые руки недостаточно.
4. Разведи руки: фигура растянется между пальцами. Увеличивай расстояние между руками для ширины, раскрывай пальцы для высоты. Рамка следует за пальцами и наклоняется вместе с ними. При повороте одной кисти относительно другой поверхность непрерывно сгибается по центру, появляется дополнительный угол на краях и линия сгиба.
5. Внутри рамки видно реальное изображение камеры с разными искажениями. Поднеси рамку к лицу — эффект применяется к лицу внутри неё.
6. Снова соедини обе пары пальцев — фигура выключится. После этого разведение рук её не возвращает. Следующее отдельное касание включает её снова.

Удержание одного касания не переключает режим многократно. Перед следующим касанием заметно разведи пальцы двух рук минимум на ~160 мс. Потеря руки камерой сама по себе не считается новым касанием. Если убрать руку, геометрия исчезнет, но выбранное состояние «включено / выключено» сохранится до следующего касания; при перезапуске камеры фигура выключена. Касание оценивается по близости кончиков пальцев в изображении, с порогом относительно размера кистей. Его принятие и состояние фигуры показаны прямо на камере.

Во время управления стеклом обычные жесты и GIF не перезапускаются. Положение рамки сглаживается; короткая потеря точек не вызывает мгновенного мигания. Это эффект обработки камеры: фон внутри рамки берётся из живого кадра.

**Отслеживание:** кисти сопоставляются между кадрами по положению, движению и метке левой/правой руки. У каждой кисти свой [One Euro Filter](https://gery.casiez.net/1euro/): он сильнее сглаживает неподвижные суставы и быстрее реагирует на движение. Краткая потеря руки не создаёт нарисованную вымышленную кисть, но её идентификатор сохраняется для восстановления. Суставы и соединения красные, с тёмной обводкой для читаемости.

**Геометрия сгиба:** четыре внешних угла постоянно привязаны к указательным и большим пальцам, включая поворот кисти через 90°. Две грани соединены подвижным центральным ребром; положение ребра вычисляется по относительному повороту захватов и локальному наклону пальцев в глубину. Грани используют непрерывную треугольную развёртку с общей линией сгиба и мягким затенением. Модель не выбирает заранее заданную фигуру по порогу поворота. Оценка глубины MediaPipe относится к каждой кисти отдельно: она применяется для ориентации, а не как общее положение двух рук в пространстве. Сгиб — управляемая геометрическая модель по данным обычной камеры; точность зависит от видимости пальцев.

**Растяжение переключает фильтры:** линза → чёрно-белое → жидкие волны → пиксельный глитч → термовизор → калейдоскоп → вихрь. Чем дальше руки друг от друга и чем сильнее раскрыты пальцы, тем дальше по цепочке эффектов. Расстояние учитывается относительно размера кистей, чтобы приближение к камере само по себе не переключало режимы. В каждом диапазоне фильтр удерживается, на границах плавно перетекает в следующий. Название эффекта и процент растяжения показаны прямо на камере; полоса под ними показывает растяжение.

**Закручивание:** подними одну руку выше другой, наклони всю рамку или поворачивай кисти относительно друг друга. Изображение закручивается вокруг центра, в том числе в чёрно-белом и остальных режимах. Наклон в обратную сторону меняет направление; верни руки ровно, чтобы ослабить скручивание. На максимальном растяжении режим «Вихрь» дополнительно создаёт анимированную спираль. «Термовизор» — цветовая стилизация кадра, а не измерение температуры.

Кнопка **«Настройки»** открывает управление камерой, привязки GIF и чувствительность. **«Суставы и скелет рук»** включены по умолчанию: на каждой кисти видны 21 красная точка и соединения пальцев. Скелет рисуется поверх искажений.

GIF и обычные анимации временно отключены. Флажок **«GIF и обычные эффекты»** под камерой возвращает чёрную область справа и наложение эффектов поверх камеры. Его выключение останавливает GIF и убирает наложение; сохранённые файлы и привязки остаются. Искажения двумя руками работают независимо от этого флажка.

| Клавиша проверки | Жест | Действие по умолчанию |
| --- | --- | --- |
| 1 | Открытая ладонь | Неоновый портал |
| 2 | V / победа | Конфетти |
| 3 | Большой палец вверх | Искры |
| 4 | Большой палец вниз | Неоновый дождь |

| 0 | Быстрый взмах открытой ладонью вправо | Конфетти |

Одна рука управляет GIF и эффектами. Видны изображение камеры, текущий жест, уверенность, FPS и полоса удержания. Взмахи определяются по движению ладони за короткое время; направление соответствует изображению в окне камеры. Щипок, стекло и взмахи — геометрические эвристики поверх точек MediaPipe, их качество зависит от освещения и ракурса.

Держи кисть целиком в кадре и показывай ладонь примерно в сторону камеры. Статический жест нужно удержать примерно 350 мс; длительное удержание не запускает анимацию каждый кадр. Для повтора убери руку или смени жест минимум на 180 мс. Пауза между действиями по умолчанию — секунда. Уверенность, время удержания и пауза настраиваются справа. Взмах — короткое событие, для него удержание не требуется; порог уверенности ладони для взмахов фиксирован на 65%. Значение уверенности щипка `100%` означает выполнение геометрического условия, а не вероятность нейросети.

## Фото по жесту

Подними средний палец, согнув остальные. Фото остаётся на камере, пока жест виден, и пропадает примерно через 120 мс после того, как опустишь палец. В настройках фото можно назначить и на другой жест. Клавиша `M` и кнопка **«Проверить жест»** показывают его на 2,6 секунды. Фото лежит в `assets/images/middle_finger.jpg` — замени этот файл, если захочешь другую картинку. Включать режим GIF и эффектов для фото не нужно.

## Как поставить свою GIF

1. Открой **«Настройки»**, включи **«GIF и обычные эффекты»** и выбери жест в списке.
2. Нажми **«Выбрать GIF…»** и выбери файл `.gif`.
3. Нажми **«Проверить жест»** — GIF появится справа в этом же окне и поверх камеры, если наложение включено.
4. Включи камеру и покажи этот жест.

GIF копируется в `assets/gifs/`, привязки автоматически сохраняются в `config.json`. Исходный файл после этого можно переместить. В выпадающем списке можно вернуть встроенный эффект. Звук в GIF не поддерживается.

`F11` разворачивает весь экран с камерой и GIF; `Esc` возвращает обычный размер. Клавиши `1–0` запускают действия вручную; `Ctrl+Space` включает/выключает камеру. Эффекты не открывают дополнительных окон.

## Где менять код

```text
main.py                   запуск и аргументы командной строки
gesture_lab/camera.py     камера OpenCV, модель, скелет кисти, поток
gesture_lab/recognition.py GPU / CPU, конвейер распознавания без очереди кадров
gesture_lab/gestures.py   щипок, взмахи, удержание и защита от повторов
gesture_lab/portal.py     две руки, сглаживание рамки, преломление камеры
gesture_lab/tracking.py   сопоставление кистей и адаптивное сглаживание суставов
gesture_lab/activation.py касание двух пар пальцев: включить / выключить фигуру
gesture_lab/surface.py    две грани, центральный сгиб, развёртка треугольников
gesture_lab/config.py     список жестов, эффекты, чтение/запись настроек
gesture_lab/effects.py    встроенные анимации на QPainter
gesture_lab/ui.py         главное окно, GIF-плеер, привязки, вызов действий
gesture_lab/model.py      загрузка и проверка модели
assets/gifs/              выбранные пользователем GIF
models/                   автоматически загружаемая модель
tests/                    проверки логики и интеграции
```

Новый эффект добавляется в `EFFECTS` в `config.py` и в `EffectCanvas.paintEvent()` в `effects.py`. Новый жест: добавь детектор в `gestures.py`, имя в `GESTURES`, передай результат из `camera.py` через `Observation`. Точка запуска действий — `MainWindow.trigger()` в `ui.py`: сюда можно подключать дополнительные функции. Сейчас действия ограничены анимациями, GIF и очисткой сцены.

Настройки создаются в `config.json` после первого изменения. Пример ручной привязки внутри `bindings`:

```json
{
  "Victory": {"type": "gif", "value": "assets/gifs/my_animation.gif"},
  "Closed_Fist": {"type": "effect", "value": "clear"}
}
```

Это фрагмент поля `bindings`, а не весь файл. Перед редактированием вручную закрой приложение. Чтобы вернуть стандартные настройки, переименуй или удали `config.json`.

## Готовые проекты и примеры

Использованы готовая модель и API [MediaPipe Gesture Recognizer](https://developers.google.com/edge/mediapipe/solutions/vision/gesture_recognizer/python), схема камеры и распознавания из [официального Python-примера Google](https://github.com/google-ai-edge/mediapipe-samples/tree/main/examples/gesture_recognizer/raspberry_pi), а также [Qt QMovie](https://doc.qt.io/qtforpython-6/PySide6/QtGui/QMovie.html) для проигрывания GIF.

Относительно примера Google: вместо `cv2.imshow` добавлен единый Qt-интерфейс с камерой и сценой; вместо устаревшего `mp.solutions` используется Tasks API; распознавание последовательных кадров перенесено в `QThread`; добавлены отслеживание двух рук, интерактивное стекло, щипок, взмахи, фильтрация повторов, настраиваемые действия, GIF и деморежим. Встроенные эффекты написаны для этого проекта.

## Проверки

```bash
.venv/bin/python -m unittest discover -s tests -v
```

Проверки используют синтетические точки кисти и временные файлы; камера и интернет для них не нужны. Для ручной проверки настоящей камеры включи её кнопкой и пройди жесты из таблицы.

Если на минимальном Linux не загружается Qt-плагин `xcb`, установи системные библиотеки X11/XCB, в частности `libxcb-cursor` (Arch) или `libxcb-cursor0` (Debian/Ubuntu). В Wayland-сессии можно запустить `QT_QPA_PLATFORM=wayland .venv/bin/python main.py`.
